# 화면정의서

각 화면은 목업 제작 시 이 정의를 기준으로 삼는다. 상태(State)는 Empty / Loading / Error / Success 4종을 기본으로 정의하고, 해당 없는 경우 생략한다.

---

# S-01. 로그인

## 목적
GitHub OAuth 로그인 진입점

## 진입 경로
최초 방문(`/`), 세션 만료 후 재방문

## 구성 요소
- 서비스 로고/이름
- 한 줄 소개 문구
- "GitHub으로 로그인" 버튼

## 상태
- Loading: OAuth 리다이렉트 중 버튼 비활성

## 인터랙션
- 버튼 클릭 → `GET /auth/github`

## 비고
로그인 상태로 접근 시 `/dashboard`로 즉시 리다이렉트

# S-03. 대시보드

## 목적
로그인 후 기본 진입점. 활동/회고 현황을 한눈에 파악하고 오늘의 회고 작성으로 유도

## 진입 경로
로그인 직후, GNB "대시보드"

## 구성 요소
- 스트릭 배지(연속 회고일, FT-08-1)
- 전체 회고 개수(FT-08-2)
- 완료한 액션포인트 개수(FT-08-3)
- 회고 히트맵(FT-08-4, GitHub 컨트리뷰션 그래프 기준 최근 1년/52주)
- Git 활동 히트맵(FT-08-5, 회고 히트맵과 별개 위젯, 동일하게 최근 1년/52주)
- "오늘의 회고 작성하기" CTA 버튼
- 액션포인트 목록(TODO만, FT-08-6)
- 최근 회고 요약 카드 리스트(FT-08-7, 최근 5개)

## 상태
- Empty: 회고/활동 이력이 전혀 없는 신규 사용자 → 기초 가이드 + 첫 회고 작성 유도 문구
- Loading: 각 위젯 스켈레톤
- Error: 위젯 단위 에러 표시(전체 화면 에러 아님)

## 상태 태그
회고 요약 카드에 `분석중` 태그 — `summaryStatus = ANALYZING`일 때 노출, 완료 시 요약 텍스트로 교체

## 인터랙션
- 액션포인트 항목은 이 화면에서는 읽기 전용 — 상태 변경(완료/실패/루틴/철회)은 S-04에서만 가능하고, 액션포인트 내용 자체는 생성 후 수정 불가
- 회고 요약 카드 클릭 → S-09 상세

## 비고
분석중 카드는 폴링 또는 재진입 시 재조회로 갱신 (실시간 푸시는 범위 밖)

# S-04. 회고 작성 — 진입 (액션포인트 리뷰)

## 목적
회고 작성 전 기존 액션포인트를 정리(리뷰)한다. Git 활동 확인과 질문 답변은 S-05에서 진행

## 진입 경로
S-03 "오늘의 회고 작성하기" 클릭

## 구성 요소
- TODO·FAILED·ROUTINE 액션포인트 목록(항목별 "완료"/"실패"/"루틴"/"철회" 토글, 전이 제한 없음, 선택 시 로컬 반영, 목록 없으면 섹션 자체 숨김)
- "다음" 버튼

## 상태
- Loading: "다음" 클릭 후 리뷰 결정 저장 대기 중 "다음" 버튼 비활성

## 인터랙션
- 액션포인트 토글 선택 → 로컬에만 반영(항목이 목록에서 즉시 빠짐, 서버 저장 아님)
- "다음" 클릭 → 로컬에 쌓인 리뷰 결정 일괄 반영 → 즉시 S-05로 전환(Git 활동 수집·질문 생성은 S-05 진입 후 진행)

## 비고
액션포인트가 하나도 없으면 이 화면은 스킵하고 바로 S-05로 진입(FT-03 참고)

---

# S-05. 회고 작성 — 활동 확인 및 질문 답변 (일괄 답변 폼)

## 목적
Git 활동을 확인하며(있는 경우) 생성된 질문 전체에 한 번에 답변하고, 제출 시 AI가 K/P/T로 재구성. 활동이 없는 경우 "오늘 무엇을 하셨나요?" 기본 질문에 답변

## 진입 경로
S-04 액션포인트 리뷰 완료(액션포인트가 없어 S-04가 스킵된 경우 S-03에서 바로)

## 구성 요소
- Git 활동 카드(Commit/Issue/PR/코드 리뷰 유형별 개수 배지, 조회 전용 참고 자료 — 활동 없는 경우엔 노출 안 함)
- 질문 목록(활동이 있으면 AI 생성 질문 최대 3개, 활동이 없으면 "오늘 무엇을 하셨나요?" 기본 질문 1개, 질문마다 답변 입력 필드)
- "다음" 버튼(모든 질문에 답변해야 활성화, 일부만 답변 시 비활성)

## 상태
- Loading: 진입 시 Git 활동·질문 API 응답 대기 중 스켈레톤 표시
- Error: 활동·질문 조회 실패 시 인라인 에러(재시도 가능, 반복 실패 시 공통 에러 정책 적용)

## 인터랙션
- 모든 질문에 답변 완료 시 "다음" 버튼 활성화(일부만 답변한 경우 비활성 유지)
- 질문 전체 답변 후 "다음" 클릭 → 즉시 S-06으로 전환(KPT 재구성 요청은 S-06 진입 후 진행)

## 비고
단계형(1문항씩 진행하는 마법사)이 아니라 질문 전체를 한 화면에서 답변받는 폼임을 목업에서 명확히 구분할 것. Git 활동 카드는 답변 입력을 자동으로 채우지 않음

# S-06. 회고 작성 — KPT 작성

## 목적
누적된 K/P/T 전체를 검토·수정 후 확정 저장(FT-05)

## 진입 경로
S-05 답변 제출(제출 즉시 전환)

## 구성 요소
- Keep/Problem/Try 목록(편집 가능, Try 최대 6개)
- 항목 추가 버튼(K/P/T 각각)
- "저장" 버튼

## 상태
- Loading: 진입 시 KPT 재구성 API 응답 대기 중 목록 영역 스켈레톤 표시, 완료 전까지 항목 추가/수정/삭제 및 "저장" 버튼 모두 비활성(재구성이 끝나면 결과가 채워지고 그때부터 편집·저장 가능. 로딩이 길어지는 경우의 대응은 추후 결정)
- Loading: 재구성 완료 후 "저장" 클릭 시 저장 요청 중 버튼 비활성
- Error: 재구성 실패 시 인라인 에러(전체 리다이렉트 아님 — 재시도 실패가 반복되면 공통 에러 정책 적용)

## 인터랙션
- Keep/Problem/Try 인라인 수정/삭제
- "+"로 항목 추가
- "저장" 클릭 → KPT 확정 저장(스트릭 +1) → 성공 시 S-07로 전환

## 비고
이 화면을 벗어나면(뒤로가기 등) 미저장 KPT 내용은 소실 — 확인 다이얼로그 노출 여부는 목업 단계 결정 사항

---

# S-07. 회고 작성 — 액션포인트 작성 (목적 그룹형)

## 목적
목적(Purpose) 그룹형 레이아웃으로 액션포인트를 작성(FT-06-1~8)

## 진입 경로
S-06 KPT 저장 완료

## 구성 요소
- 목적(Purpose)별 그룹 카드 목록 — 그룹 헤더는 목적 문구(+수정 버튼), 그 아래 해당 목적에 연결된 액션포인트 리스트(항목마다 출처 배지 표시: "AI 제안" / "직접 추가" / "실패·루틴에서 이어짐"). 액션포인트가 0개인 그룹은 "액션포인트가 없는 목적은 저장되지 않습니다" 안내 문구를 인라인으로 상시 표시(항목이 0개인 동안 계속 노출, 완료 클릭과 무관)
- 각 액션포인트 항목의 수정/삭제 버튼
- 그룹 하단 "+" 버튼(해당 목적으로 액션포인트 인라인 추가)
- 화면 맨 아래 "+ 목적 추가" 버튼(목적 문구만 인라인 입력해 빈 그룹 생성)
- "완료" 버튼

## 상태
- Loading: 액션포인트·목적 후보 생성 대기 중(진입 시 자동), 스켈레톤 위에 "회고를 기반으로 액션포인트를 만들고 있습니다" 안내 문구 표시, 완료 전까지 그룹/항목 조작 불가(로딩이 길어지는 경우의 대응은 추후 결정)
- Loading: "완료" 클릭 시 일괄 저장 요청 중 버튼 비활성

## 인터랙션
- 액션포인트 항목 텍스트 수정/삭제 → 로컬 반영(FT-06-3)
- 그룹 하단 "+"로 인라인 입력 추가 → 로컬 반영(FT-06-4)
- 그룹 헤더 수정 버튼으로 목적 문구 수정 → "잦은 목적 수정은 방향성을 해칠 수 있어요" 안내 노출 후 로컬 반영(같은 그룹 액션포인트 표시 함께 갱신, FT-06-5)
- 액션포인트 카드를 다른 목적 그룹으로 드래그 앤 드롭 → 소속 그룹 변경(로컬 반영, FT-06-6)
- "+ 목적 추가" → 빈 그룹 생성(로컬 반영, FT-06-7)
- "완료" 클릭 → 액션포인트가 0개인 목적 그룹은 저장 대상에서 제외하고 나머지 목적·액션포인트를 일괄 서버 저장(TODO 상태 생성) 후 S-03 복귀(FT-06-8)

## 비고
출처 배지는 진입 시점에 정해짐 — Try 기반 AI가 목적·액션포인트 후보를 함께 생성한 항목은 "AI 제안"(각 그룹에 자동 배치), FT-03에서 "실패"/"루틴"으로 리뷰된 항목의 복사본은 "실패·루틴에서 이어짐"(원본 목적 그룹 아래 노출), 사용자가 그룹 하단 "+"로 직접 입력한 항목은 "직접 추가". 목적 드롭다운 없음 — 액션포인트는 항상 소속된 그룹(후보 생성 시 배정 또는 드래그로 변경된 그룹) 기준으로만 목적이 정해짐. 목적은 별도 관리 화면 없이 이 화면에서만 추가·수정 가능. FT-03에서 리뷰한 기존 액션포인트 원본의 content는 여기서 수정하지 않음(수정하고 싶으면 새 항목 추가). 액션포인트는 생성 후(저장 이후) 수정 불가·중복 체크 없음·존댓말/표준어 보정 없이 입력 그대로 저장. 그룹을 만들었지만 액션포인트를 하나도 추가하지 않은 경우도 동일하게 저장 대상에서 제외됨(별도 예외 없음)

# S-09. 회고 상세

## 목적
개별 회고의 전체 내용(질문/답변, K/P/T, AI 요약·인사이트) 열람 및 삭제

## 진입 경로
S-08 카드 클릭, S-03 요약 카드 클릭

## 구성 요소
- 회고 날짜
- 질문/답변 전체
- K/P/T
- AI 요약/인사이트(또는 "분석중" 상태)
- 해당 회고로 생성된 액션포인트 목록
- "삭제" 버튼

## 상태
- Loading: 상세 조회 중
- 분석 미완료 시 요약/인사이트 영역에 "분석중" 표시

## 인터랙션
- "삭제" 클릭 → 확인 다이얼로그("액션포인트도 함께 삭제됩니다") → 확인 시 삭제 후 S-08 복귀

## 비고
수정 버튼 없음 (회고는 수정 불가 원칙)

# 공통 에러 표시

전 화면 공통으로 별도 "에러 화면"을 두지 않는다. API 실패 시 토스트/얼럿 형태로 에러 메시지를 노출한 뒤 `/`로 리다이렉션한다 ([[03-user-flow#5-공통-에러-정책]] 참고). 구체적 UI 컴포넌트는 목업 단계에서 확정한다.
