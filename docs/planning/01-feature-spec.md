## FT-03. 액션포인트 리뷰 (회고 작성 진입)

| 항목 | 내용 |
| --- | --- |
| 설명 | 기존 TODO·FAILED·ROUTINE 상태 액션포인트가 있으면 목적(Purpose)별 그룹 카드로 표시(레이아웃은 FT-06-1과 동일, 조회 전용 — 그룹 헤더 수정·드래그·추가 없음)하고, 항목별로 "완료" / "실패" / "루틴" / "철회" 중 하나를 선택받는다. 선택한 결정은 버튼과 카드 배경이 상태별 색으로 바뀌는 것으로 화면에 즉시 반영되며(항목은 목록에서 사라지지 않고 계속 표시), 서버 저장은 다음 단계(FT-04-1)로 넘어갈 때 전체 결정을 일괄 반영한다. 완료를 선택하면 상태를 `DONE`으로 변경해 더 이상 노출하지 않는다. 실패를 선택하면 다음에 다시 수행하는 것으로 보아 상태를 `FAILED`로 변경하고(`failureCount` +1) 다음 회고 진입 시에도 다시 노출된다. 루틴을 선택하면 이미 수행했지만 성격상 다음에도 반복 수행이 필요한 항목으로 보아 상태를 `ROUTINE`으로 변경하고 다음 회고 진입 시에도 계속 노출된다. 철회를 선택하면 불필요해진 항목으로 보아 상태를 `REMOVED`로 변경해 더 이상 노출하지 않는다 |
| 트리거 | 회고 작성 진입 화면 로드 |
| 관련 화면 | S-04 회고작성 - 진입 |
| 비고 | 액션포인트가 하나도 없으면 이 단계는 스킵하고 바로 다음 단계로 진행. 액션포인트 상태 모델은 `TODO`/`DONE`/`FAILED`/`ROUTINE`/`REMOVED` 5분류로 확정(05번 참고). 현재 상태와 무관하게 4개 결정 모두 선택 가능(전이 제한 없음). 선택한 결정은 항목별로 로컬에 임시 보관되다가 다음 단계로 넘어갈 때 일괄 서버 반영된다 — 위저드 전반("다음 단계 클릭 시 저장")에 맞춰 정리한 방식이며, 그 이전에 있었던 "즉시 저장(절차저장형)" 방식은 폐기됨. 리뷰 화면과 대시보드는 `TODO`·`FAILED`·`ROUTINE` 상태를 모두 조회 대상으로 포함해야 함(복수 상태 필터, 구현 시 상세 결정) |

## FT-04. 회고 질문 생성 및 답변

### FT-04-1. Git 활동 수집 및 AI 질문 생성

| 항목 | 내용 |
| --- | --- |
| 설명 | 회고 작성 진입 시 "오늘" 공개된 활동(commit 작성, issue 작성, PR 작성, PR 리뷰 작성)을 API로 가져와 조회한다. 활동이 있으면 이를 기반으로 예상 질문 최대 3개를 생성하고, 활동이 없으면 "오늘 무엇을 하셨나요?" 질문 후 입력을 받아 그 내용을 기반으로 질문을 생성한다 |
| 트리거 | FT-03 완료 직후 |
| 관련 화면 | S-04 회고작성 - 진입(활동 없음 시 직접 입력 UI 포함) |
| 비고 | 질문 개수는 최대 3개. 활동량이 적으면 3개 미만일 수 있음 |

### FT-04-2. 답변 폼 + KPT 변환

| 항목 | 내용 |
| --- | --- |
| 설명 | 생성된 질문 전체와 함께 FT-04-1에서 수집한 오늘의 Git 활동(Commit/Issue/PR/코드 리뷰, 유형별 개수 배지 포함)을 한 화면에 표시해 답변 작성 시 참고하게 한다. 질문에는 한 번에 답변받는 폼으로 제출하며, 전체 답변 제출 시 AI가 각 답변을 K/P/T 중 하나 이상으로 재구성해 정리한다 |
| 트리거 | FT-04-1 완료 후 |
| 관련 화면 | S-05 회고작성 - 질문답변 |
| 비고 | AI는 답변을 "재구성"만 한다. 답변에 없는 내용을 창작하지 않는다 (설계 원칙). Git 활동 카드는 조회 전용 참고 자료이며 답변 입력을 자동으로 채우지 않는다. 활동이 없는 경우(FT-04-1)에는 활동 카드를 노출하지 않는다 |

## FT-06. 액션포인트 작성 (목적 그룹형)

### FT-06-1. 목적 그룹 레이아웃

| 항목 | 내용 |
| --- | --- |
| 설명 | 액션포인트는 화면에서 목적(Purpose)별로 그룹핑되어 표시된다. 그룹 헤더는 연결된 목적 문구이며, 그 아래 해당 목적에 연결된 액션포인트가 나열된다 |
| 트리거 | FT-05(KPT 저장) 완료 후 S-06 최종확인 화면 진입 |

| 비고 | 목적은 필수값(FT-06-4)이므로 목적 없는 액션포인트를 위한 별도 그룹은 없음. 단, 목적 그룹 자체는 액션포인트 없이 임시로 존재할 수 있다(FT-06-7로 생성 직후, 또는 FT-06-6 드래그로 비워진 경우) — 완료 시점 검증은 FT-06-8 참고 |

### FT-06-2. Try 기반 AI로 목적, 액션포인트 생성

| 항목 | 내용 |
| --- | --- |
| 설명 | 확정된 Try 목록을 기반으로 AI가 액션포인트 후보와 그에 연결할 목적을 함께 생성한다 — 기존 활성 목적 중 적합한 것이 있으면 그 목적 그룹 아래 "후보"로 노출하고, 없으면 새 목적 그룹을 후보 상태로 함께 제안한다. FT-03에서 "실패"/"루틴"으로 리뷰된 기존 항목의 복사본은 원본의 목적 그룹 아래 후보로 노출된다 |

### FT-06-3. 액션포인트 후보 수정

### FT-06-8. 액션포인트 작성 완료

| 항목 | 내용 |
| --- | --- |
| 설명 | 액션포인트 작성 단계에서 "완료" 클릭 시, 액션포인트가 0개인 목적 그룹이 없는지 먼저 검증한다. 문제가 없으면 FT-06에서 로컬에 쌓인 목적·액션포인트(후보 수정분, 직접 추가 항목, 목적 수정, 드래그로 변경된 목적 연결 포함)를 서버에 일괄 저장한 뒤 위저드를 종료하고 대시보드로 이동한다. 액션포인트가 0개인 목적 그룹이 있으면 저장을 진행하지 않고 위저드를 종료하지 않은 채 해당 그룹에 빨간색으로 "액션포인트가 없는 목적은 생성할 수 없습니다" 문구를 노출한다 — 그 그룹에 액션포인트를 추가해야 완료할 수 있다. 회고 본문(KPT)은 FT-05에서 이미 저장되었으므로 재저장하지 않는다. "건너뛰기" 클릭 시에는 FT-06에서 만든 목적·액션포인트가 없는 것으로 보아 저장할 대상 없이 바로 종료한다 |
| 트리거 | 액션포인트 작성 화면에서 "완료" 또는 "건너뛰기" 클릭 |
| 관련 화면 | S-06 → S-03(대시보드 복귀) |
| 비고 | 목적 그룹을 하나도 만들지 않아 액션포인트가 전혀 없는 경우는 빈 그룹 검증 대상이 아니며, 그대로 완료(또는 건너뛰기)로 인정된다. 대시보드에는 이 시점의 저장 결과가 이미 반영된 상태로 진입한다. 저장(또는 건너뛰기) 성공은 FT-07(AI 회고 분석)의 트리거가 된다 |

## FT-07. AI 회고 분석 (제목·요약·인사이트)
