# 디자인 시스템 검토 체크리스트 (백엔드 개발자용)

Claude Design이 만든 디자인 시스템 결과물을 받았을 때, 우리가 지정했던 값·규칙이 잘 지켜졌는지 확인하는 문서다. 디자인 지식이 없어도 아래 순서대로 "값 대조"만 하면 된다.

## 사용법

1. Claude Design 출력물(CSS 변수 또는 Tailwind config 텍스트)을 준비한다
2. 아래 체크리스트를 위에서부터 순서대로 확인한다
3. 하나라도 실패하면 그 항목만 다시 요청(Remix) — 전체를 다시 만들 필요 없다
4. 6개 카테고리 전부 통과해야 다음 단계(첫 화면 제작)로 진행 가능

## 미니 용어 사전 (디자인 용어 → 개발자 비유)

| 디자인 용어 | 쉬운 설명 | 개발자 비유 |
| --- | --- | --- |
| 토큰(token) | 재사용되는 디자인 값(색, 크기 등) | 상수(constant) / 환경변수 |
| 시맨틱 컬러 | "의미"로 이름 붙인 색 (예: fill-primary) | 매직넘버 대신 쓰는 named constant |
| hover / active / disabled | 마우스 올림 / 눌림 / 비활성 상태 | 상태값(state) enum |
| focus-visible | 키보드로 포커스됐을 때만 보이는 테두리 | 조건부 렌더링(마우스 클릭 시엔 안 보여도 됨) |
| 톤앤매너 | 서비스 성격을 나타내는 형용사 세트 | 코드 네이밍 컨벤션 같은 일관성 규칙 |
| 명도 대비(contrast ratio) | 글자와 배경이 얼마나 구분되는지 수치 | 접근성 최소 기준값(SLA 같은 것) |
| motion / duration | 애니메이션이 움직이는 시간 | 타임아웃 값 |

## 체크리스트

### 1. 색상 값이 그대로 왔는지

- [x] Point(`#18F293`), Background(`#FFFFFF`), Text(`#3E3E40`), Surface(`#FBFBFC`, `#FEFEFE`) 5개 값이 결과물에 정확히 이 hex 코드로 들어있다

왜 중요한가: 이 5개는 이미 확정한 "원본 값"이다. AI가 "더 예쁘게" 임의로 바꾸면 안 된다 — config 값이 배포 환경에서 몰래 바뀌면 안 되는 것과 같다.

### 2. 파생된 상태 색상이 원본에서 나온 게 맞는지

- [x] hover/active/disabled 색상이 위 5개 원본 색에서 투명도나 밝기만 조정해서 나왔다
- [ x] 원본과 전혀 관계없는 새 색(갑자기 등장한 파란색, 보라색 등)이 섞여있지 않다

왜 중요한가: 상태 색은 원본에서 파생돼야 일관성이 생긴다. 근거 없는 색이 끼어들면 "이 값은 어디서 나온 거지?"가 된다.

### 3. 서비스 성격(톤앤매너)에 맞는지

- [x] 채도 높은 배경색이나 화려한 그라디언트가 없다
- [x] 불필요한 장식(일러스트, 아이콘 남발)이 없다
- [x] 예시 문구가 있다면 해요체("~해요", "~인가요")이고, "실패"/"미완료" 같은 평가적 단어가 없다

왜 중요한가: "차분하고 담백하고 다정한" 방향과 반대로 가면 지금까지 정한 게 무의미해진다.

### 4. 상호작용 상태(인터랙션)가 5개 다 있는지

- [x] 버튼/카드 등 클릭 가능한 요소마다 rest(기본) / hover(마우스 올림) / focus-visible(키보드 포커스) / active(눌림) / disabled(비활성) 5개 상태가 전부 정의돼 있다
- [x] focus-visible이 빠지지 않았다 (제일 잘 빠뜨리는 항목)
- [x] 애니메이션 시간이 100~300ms 사이다 (500ms 넘는 게 있으면 실패)

왜 중요한가: 상태 하나가 빠지면 enum의 case 하나를 처리 안 한 것과 같은 버그 상태다.

### 5. 참고했던 다른 서비스 요소가 잘못 섞여 들어오지 않았는지

- [x] Linear를 참고했다고 어두운 배경(다크 테마) 톤이 그대로 들어오지 않았다
- [x] Toss를 참고했다고 모바일 전용 컴포넌트(하단 시트, 하단 고정 버튼 등)가 들어오지 않았다 (우리는 데스크톱 전용)

왜 중요한가: "요소만 참고"하기로 했는데 통째로 들어오면, 다른 프로젝트 설정 파일을 그대로 복붙해서 생기는 사고와 같다.

### 6. 글자가 잘 읽히는지 (명도 대비)

- [x] 텍스트 색과 배경색을 [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/)에 넣어서 확인했다
- [x] 일반 본문 글자는 4.5:1 이상이다
- [x] 큰 글자(제목 등)나 버튼은 3:1 이상이다

왜 중요한가: 이 숫자 밑으로 내려가면 시력이 안 좋거나 화면이 밝은 곳에서 못 읽는 사람이 생긴다. 최소 성능 기준이라고 생각하면 된다.

## 결과 처리

- 6개 카테고리 전부 체크됐다 → 다음 단계(첫 화면 제작)로 진행
- 하나라도 실패 → 실패한 항목만 "이 부분만 다시 만들어줘"라고 요청 (전체 재생성 불필요)
